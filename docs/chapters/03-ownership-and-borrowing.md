# 03. 所有權、借用 (Ownership & Borrowing)

所有權（Ownership）與借用（Borrowing）是 Rust 最關鍵的核心靈魂。它是 Rust **不需要垃圾回收機制（GC）** 卻能保證**絕對記憶體安全**的秘密武器。

初學者第一次接觸時常感到抽象，本單元我們用最直觀的**「實物比喻」**與**「互動動畫模擬」**，帶您一步步輕鬆攻克！

---

## 1. 什麼是所有權？用「買筆電」來比喻

想像你走進實體店買了一台全新筆電：

1. **唯一擁有者**：你刷卡買下這台筆電，在發票與產權上，**這台筆電的擁有者就是你**（Rust 第一原則：每個值都有一個擁有者變數）。
2. **不能影分身**：在物理世界中，同一台筆電不可能同時屬於你又屬於別人（Rust 第二原則：同一時間只能有一個擁有者）。
3. **離開宿舍帶走垃圾**：當你畢業搬出宿舍（變數離開大括號作用域 `{}`）時，你留下的私人物品會被學校宿管自動清理回收（Rust 第三原則：擁有者離開作用域時，記憶體自動釋放 Drop）。

## 2. 堆疊 (Stack) 與 堆積 (Heap) 的記憶體地圖

電腦記憶體分成兩大區域，這決定了資料是「複製」還是「轉移」：

| 記憶體區域 | 特性與比喻 | 存放的資料型別 | 所有權行為 |
| :--- | :--- | :--- | :--- |
| **堆疊 (Stack)** | ⚡ 速度極快、固定大小、如同一疊盤子先進後出 | 數字 `i32`, 浮點 `f64`, 布林 `bool` | **完整複製 (Copy)** |
| **堆積 (Heap)** | 📦 空間極大、大小動態未知、需要向系統申請鑰匙 | 字串 `String`, 向量 `Vec` | **所有權轉移 (Move)** |

> 💡 **為什麼 s1 會失效？**  
> 如果 Rust 允許 `s1` 和 `s2` 同時有效，那麼當兩者離開大括號時，電腦會嘗試釋放同一塊 Heap 記憶體兩次（這就是 C/C++ 最致命的 **Double Free** 重複釋放漏洞）。Rust 透過將 `s1` 標記為失效（Move），從根本上解決了這個世紀難題！

## 4. 借用規則：圖書館「借書」比喻

如果每次把字串傳給函式，所有權都被拿走，那我們寫程式豈不是寸步難行？  
這時候我們可以使用 **參照（`&`）**，也就是向擁有者 **借用（Borrowing）**！

### 📚 借用的黃金法則
借用就跟在圖書館借書的日常規則一模一樣：
1. **可以很多人同時「安靜閱讀」**：只要大家都不修改，可以有無限多個不可變參照 `&T`。
2. **修改塗鴉只能「一人獨佔」**：如果要修改內容，同一時間只能有一個可變參照 `&mut T`。
3. **不能邊看邊改**：有讀者在看書時，作者絕不能突然拿立可白跑來改字（這就是防止多執行緒資料競爭 Data Race）！

## 6. 本單元心法口訣

- **給出值**：`let b = a;` ➔ 所有權移走，原變數失效（除非型別有 Copy）。
- **借出看不改**：`&a` ➔ 唯讀參照，大家都可以看，不可修改。
- **借出允許改**：`&mut a` ➔ 唯一獨佔，同一時間只能有一人能改。
