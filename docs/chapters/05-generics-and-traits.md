# 05. 泛型、特徵 (Generics & Traits)

在寫程式的過程中，你一定遇過這種令人無奈的情境：
> 「我只是想寫一個尋找陣列最大值的函式，難道要為整數寫一個 `largest_i32`、為浮點數寫一個 `largest_f64`、為字串寫一個 `largest_str` 嗎？」

如果每遇到一種型別就要複製貼上一次，程式碼很快就會變得臃腫且難以維護！

為了解決這個難題，Rust 提供了兩大終極武器：
1. **泛型 (Generics)**：程式碼的「萬用金屬模具」，抽換資料型別毫不費力。
2. **特徵 (Traits)**：型別的「技能檢定證照」，確保丟進來的資料具備指定的能力。

最棒的是，Rust 採用了 **「零成本抽象 (Zero-Cost Abstractions)」** —— 編譯器會在編譯時自動進行單態化（Monomorphization），替用到的型別量身打造最頂級的原生機器碼，執行速度與手寫完全相同，沒有任何額外負擔！

## 3. 🧩 深度拆解：三大模組核心思維

### ① 泛型 (Generics)：把「型別」也當成參數傳遞
一般函式的參數傳遞的是「數值」，而泛型傳遞的是「型別」：
- 我們通常用大寫字母 `T` (Type 的縮寫) 作為預設型別代號。
- 無論是函式還是結構體，只要套上 `T`，就能適應各種型別。
- **單態化（Monomorphization）的秘密**：當你在程式中同時使用了 `Point<i32>` 與 `Point<f64>`，Rust 編譯器在打包成執行檔時，會自動替你複製生成兩份極度最佳化的專屬原生機器碼，執行效能 100% 滿分！

```
【傳統重複程式碼】              【Rust 泛型萬用模具】
fn max_i32(a, b) -> i32                fn max<T>(a: T, b: T) -> T
fn max_f64(a, b) -> f64    ======>     (編譯器在編譯期自動按需求生成機器碼)
fn max_str(a, b) -> str
```

### ② 特徵 (Traits)：宣告能力，而非繼承關係
Rust 拋棄了傳統物件導向複雜的「父子繼承關係」，而是採用更加靈活的 **「特徵合約組合」**：
- 只要型別實作了某個特徵（例如 `Playable`），就等於簽署了合約，保證提供該特徵所規範的所有方法。
- **預設實作 (Default Implementation)**：特徵還可以提供預設程式碼！如果某個型別沒有特製的邏輯，就直接繼承預設行為，不必重複撰寫 boilerplate 程式碼。

### ③ 特徵約束 (Trait Bounds)：有證照才准進門
當泛型遇到具體操作時（例如用 `+` 做加法、用 `>` 比大小、或用 `println!` 印到螢幕）：
- Rust 編譯器會嚴格把關：「萬一有人傳進一個不能比較的型別，程式不就當機了嗎？」
- 我們透過特徵約束（例如 `T: PartialOrd + Display`），在門口立下規矩：「只有攜帶比較與列印護照的資料，才准放行！」
- 當約束條件很長時，可以使用 **`where` 子句**，讓函式簽章保持乾淨易讀。

### 範例二：多媒體播放器介面 (Trait 多型與介面統一)
- **核心觀念**：
  - 定義 `trait Playable`，規範只要是能播的媒體都必須有 `play(&self)` 方法。

### 範例三：比大小冠軍判斷器 (特徵約束 Trait Bound)
- **核心觀念**：
  - 函式 `print_champion<T: Display + PartialOrd>` 結合了泛型與兩項特徵約束。

## 5. 💡 本章核心重點速記

1. **泛型 (Generics)** 讓你寫出萬用模具，抽換型別不需複製貼上。
2. **特徵 (Trait)** 是 Rust 實現多型（Polymorphism）的靈魂，憑能力說話。
3. **預設實作 (Default Impl)** 讓介面更具彈性，減少重複樣板程式碼。
4. **特徵約束 (Trait Bound)** 與 **`where`** 在編譯期把關型別能力，保證 100% 型別安全。
5. **零成本抽象 (Zero-Cost Abstractions)**：編譯器透過單態化生成專屬機器碼，完全沒有任何執行時的虛擬方法表（vtable）開銷！
